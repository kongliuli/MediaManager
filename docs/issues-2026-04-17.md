## 问题一：FfprobeMetadataService 异步竞态（中风险）

**文件**: [src/MediaManager.Services/Metadata/FfprobeMetadataService.cs](../src/MediaManager.Services/Metadata/FfprobeMetadataService.cs)  
**行号**: 43–54

### 问题描述

当前代码使用 `Task.WhenAny(outputTask, errorTask, exitTask)` 等待三个任务中任意一个完成后，立即读取 `process.ExitCode`。但 `WhenAny` 返回的可能是 `outputTask` 或 `errorTask`，此时进程未必已退出，`ExitCode` 读取会抛出 `InvalidOperationException`（进程尚未退出时访问 ExitCode 是未定义行为）。

```csharp
// 当前代码（有问题）
var completedTask = await Task.WhenAny(outputTask, errorTask, exitTask);
// ...
if (process.ExitCode != 0)  // ← 进程可能还未退出
```

### 修改方案

必须等待进程真正退出后再读取 ExitCode，同时确保 stdout/stderr 已全部读完（避免管道死锁）：

```csharp
// 修改后
var outputTask = process.StandardOutput.ReadToEndAsync(ct);
var errorTask  = process.StandardError.ReadToEndAsync(ct);

await process.WaitForExitAsync(cancellationTokenSource.Token);

if (process.ExitCode != 0)
{
    var error = await errorTask;
    throw new Exception($"ffprobe 执行失败: {error}");
}

var output = await outputTask;
return ParseMetadata(output, filePath);
```

> `WaitForExitAsync` 是 .NET 5+ 提供的方法，项目目标框架 net8.0 可直接使用。  
> 注意：必须先启动 stdout/stderr 的异步读取，再调用 `WaitForExitAsync`，否则管道缓冲区满会导致进程挂起。

## 问题二：FileScannerService 未处理目录权限异常（中风险）

**文件**: [src/MediaManager.Services/Scanning/FileScannerService.cs](../src/MediaManager.Services/Scanning/FileScannerService.cs)  
**行号**: 40–63

### 问题描述

`Directory.EnumerateFiles` 和 `Directory.EnumerateDirectories` 在遇到无权限目录（如 `C:\System Volume Information`、`C:\Windows\System32` 的部分子目录）时会抛出 `UnauthorizedAccessException`，导致整个扫描任务中断，已发现的文件全部丢失。

```csharp
// 当前代码（无异常处理）
foreach (var filePath in Directory.EnumerateFiles(directory))
foreach (var subDirectory in Directory.EnumerateDirectories(directory))
```

### 修改方案

对每个目录的枚举单独捕获异常，跳过无权限目录，继续扫描其他目录：

```csharp
IEnumerable<string> files;
try
{
    files = Directory.EnumerateFiles(directory);
}
catch (UnauthorizedAccessException)
{
    yield break;
}

foreach (var filePath in files)
{
    ct.ThrowIfCancellationRequested();
    if (IsSupportedFormat(filePath))
        yield return filePath;
}

if (recursive)
{
    IEnumerable<string> subDirs;
    try
    {
        subDirs = Directory.EnumerateDirectories(directory);
    }
    catch (UnauthorizedAccessException)
    {
        yield break;
    }

    foreach (var subDirectory in subDirs)
    {
        ct.ThrowIfCancellationRequested();
        await foreach (var filePath in DiscoverFilesAsync(subDirectory, true, ct))
        {
            ct.ThrowIfCancellationRequested();
            yield return filePath;
        }
    }
}
```

## 问题三：DuplicateGroup.ReclaimableSize 假设文件大小一致（低风险）

**文件**: [src/MediaManager.Core/Models/DuplicateGroup.cs](../src/MediaManager.Core/Models/DuplicateGroup.cs)  
**行号**: 10–12

### 问题描述

当前计算公式为 `Files[0].FileSize × (Files.Count - 1)`，假设组内所有重复文件大小完全相同。实际场景中，同内容文件经过不同编码工具处理后，文件大小可能存在细微差异（如 ID3 标签长度不同），导致可回收空间计算偏低或偏高。

```csharp
// 当前代码
public long ReclaimableSize => Files.Count > 1
    ? Files[0].FileSize * (Files.Count - 1)
    : 0;
```

### 修改方案

保留一个最小文件（视为"保留版本"），其余文件大小之和即为可回收空间：

```csharp
public long ReclaimableSize => Files.Count > 1
    ? Files.Sum(f => f.FileSize) - Files.Min(f => f.FileSize)
    : 0;
```

## 问题四：SearchAsync 关键词仅匹配文件名（低风险）

**文件**: [src/MediaManager.Data/Repositories/MediaRepository.cs](../src/MediaManager.Data/Repositories/MediaRepository.cs)  
**行号**: 31–36

### 问题描述

关键词搜索只对 `FileName` 字段做 LIKE 匹配，不覆盖音频的 `Title`、`Artist`、`Album` 等 ID3 元数据字段，用户按歌手名或专辑名搜索时无结果。

```csharp
// 当前代码
dbQuery = dbQuery.Where(f =>
    EF.Functions.Like(f.FileName, keyword)
);
```

### 修改方案

扩展搜索范围到元数据字段，使用 EF Core 的 TPH 类型转换：

```csharp
dbQuery = dbQuery.Where(f =>
    EF.Functions.Like(f.FileName, keyword) ||
    (f is AudioFile &&
        (EF.Functions.Like(((AudioFile)f).Title ?? "", keyword) ||
         EF.Functions.Like(((AudioFile)f).Artist ?? "", keyword) ||
         EF.Functions.Like(((AudioFile)f).Album ?? "", keyword))) ||
    (f is VideoFile &&
        EF.Functions.Like(((VideoFile)f).Title ?? "", keyword))
);
```

> 注意：EF Core 对 TPH 子类型的 LINQ 转换支持有限，建议先通过集成测试验证 SQL 生成是否正确。
